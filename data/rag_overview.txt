Retrieval-Augmented Generation (RAG) is a technique that combines information
retrieval with text generation. Instead of relying only on a language model's
training data, a RAG system first retrieves relevant passages from a knowledge
base and then uses them as context for generating an answer.

A typical RAG pipeline has three stages:

1. Indexing: documents are split into chunks, converted into vector embeddings,
   and stored in a vector database such as FAISS, Pinecone, or Weaviate.
2. Retrieval: when a user asks a question, the system embeds the query and
   finds the most similar chunks using cosine similarity.
3. Generation: the retrieved chunks are inserted into a prompt, and a large
   language model produces a grounded answer with citations.

RAG reduces hallucinations because the model is constrained to answer from the
provided context. It also keeps knowledge fresh: updating the document store
is cheaper than retraining a model.

Common chunking strategies include fixed-size windows with overlap, recursive
splitting on separators like paragraphs and sentences, and semantic chunking.
A chunk size of 500 to 1000 characters with 10 to 20 percent overlap works
well for most question-answering workloads.

Evaluation of RAG systems typically measures retrieval quality (recall of
relevant chunks) and generation quality (faithfulness to the context and
answer relevance). Frameworks like RAGAS provide automated metrics for both.
